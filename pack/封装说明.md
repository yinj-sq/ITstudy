# ITstudy 封装说明

适用版本：ITstudy v6.1.0 ｜ 权利人：YINJUN ｜ 授权范围：仅授权个人使用，非商业用途。

> **这篇文档解决什么问题**：把 ITstudy 源码打包成 Windows 安装程序
> （`ITstudy-v6.1.0-Setup.exe`），让不懂技术的人也能双击安装运行。
>
> **谁需要读**：
> - 负责发布安装包的人 → 一~五节（封装流程 + 构建前检查）
> - 测试安装包的人 → 六节（安装后验证）
> - 遇到构建/安装问题的人 → 七节（常见问题）
>
> **术语速查**：
> - **NSIS**：制作 Windows 安装程序的工具（开源软件，需单独安装）
> - **makensis**：NSIS 的编译命令（把安装脚本编译成 .exe 安装包）
> - **installer.nsi**：安装脚本（文本文件），描述"安装包里放什么、安装时做什么"
> - **构建产物**：编译生成的安装包文件（`pack\ITstudy-v6.1.0-Setup.exe`）
> - **wheel 包**：Python 依赖的预编译格式（离线安装依赖时用到）

## 一、封装目录内容
`pack` 目录集中保存 ITstudy v6.1.0 的 NSIS 安装包封装文件、素材和操作指南：

| 文件 | 说明 |
|------|------|
| `installer.nsi` | NSIS 安装脚本（描述安装行为），编译后输出 `ITstudy-v6.1.0-Setup.exe` |
| `build-installer.ps1` | 一键构建脚本（封装了 makensis 命令，推荐用它） |
| `license-v6.0.txt` | 随包安装的 v6.0 授权许可纯文本（UTF-8 BOM） |
| `license-v6.0.rtf` | 安装向导授权许可页（RTF Unicode，避免中文乱码） |
| `assets/app.ico` | 安装器和卸载器图标 |
| `assets/app-icon-source.svg` | 应用图标源文件（用于后续改图标） |
| `assets/nsis-header.bmp` | 安装向导顶部横幅图 |
| `assets/nsis-welcome.bmp` | 安装向导欢迎页图片 |
| `ICON_DESIGN_GUIDE.md` | 应用图标设计规范（配合 `assets/app-icon-source.svg` 使用） |
| `nssm.exe` | 可选工具：将 Nginx 注册为 Windows 服务（部署期使用，不随安装包分发） |
| `封装说明.md` | 本文档：封装流程、项目结构、清单与排障 |

> **目录边界**：`pack` 只存放安装包构建相关内容（脚本、素材、授权文本、本文档）。
> 应用运行代码保留在项目根目录及业务目录，安装脚本通过相对路径从根目录取文件——
> 不要把运行代码挪进 `pack`，否则安装包会缺文件。

> 历史版本页面模板归档已清除，如需追溯可从 git 历史获取：
> `git show 90aee3b:docs/archive/do_exam.html.archived`。

## 二、环境准备（构建机器）
在**要生成安装包的电脑**上准备（与运行 ITstudy 的机器可以不是同一台）：

| 项 | 是否必需 | 说明 |
|----|----------|------|
| NSIS 3.x | ✅ 必需 | 制作安装包的工具。确保 `makensis.exe` 在 PATH 中（或在默认安装目录） |
| Python 3.10+ | ✅ 必需 | 安装时勾选 "Add Python to PATH"（构建脚本要用） |
| 管理员权限 | ✅ 必需 | 安装脚本要注册 Windows 服务、写入 Program Files |
| PostgreSQL 12+ | ⚠️ 仅测试时需要 | 验证安装包能否正常连接数据库（目标机器上需要，构建机器可不装） |

## 三、构建命令（生成安装包）
在**项目根目录**执行（推荐方式）：

```powershell
& .\pack\build-installer.ps1
```

> 也可以用等价的底层命令（进入 `pack` 目录后执行）——**先**校准预压缩副本：
> ```powershell
> python -X utf8 ..\tools\precompress_static.py --refresh-only
> makensis /INPUTCHARSET UTF8 installer.nsi
> ```
>
> `build-installer.ps1` 依次执行：下载离线 wheels（**按 `constraints.txt` 钉版本**、
> 仅接受 wheel）→ **校准 `.gz` 预压缩副本** → makensis。第二步不可省：nginx
> `gzip_static` 只要 `.gz` 存在就原样下发，源文件改过而 `.gz` 未重建时浏览器拿到
> 的是旧脚本（2026-09-25 实测 5 个陈旧，其中 PPTist 入口页停留在 V5.0.1 之前）。
> `tests/test_review_fixes_0925.py` 有用例守住「所有 `.gz` 与源文件一致」。

**成功标志**：`pack\` 下出现 `ITstudy-v6.1.0-Setup.exe` 且终端输出无 ERROR。
构建通常几分钟内完成（首次会全量复制静态资源）。

> 构建产物（安装包 .exe）不需要提交到源码仓库，除非发布流程要求保留。

### 打包清单核对（`/V4`，发布前必做）

```powershell
makensis /INPUTCHARSET UTF8 /V4 installer.nsi > pack.log 2>&1
Select-String -Path pack.log -Pattern 'venv|site-packages' | Measure-Object
```

**预期**：`venv` 命中 **7** 行、`site-packages` 命中 **0** 行（7 行全是脚本自身对
`$INSTDIR\venv` 的创建/操作语句）；`tools\e2e_`、`tools\review_`、`审查报告` 均应命中 **0** 行。这不是形式主义——`File` 命令若在**单个文件名**上
误用 `/r`，NSIS 会把该名字当查找掩码、从上层目录起**遍历整棵源码树**把同名文件按
相对路径还原打进包（实测 **110 条 venv 引用**）。装机后这些文件落在 `site-packages`
下形成只含零碎文件的**裸目录**，`import numpy` 之类会命中空壳包而崩（openpyxl 曾因此
整片挂掉，site-packages 顶层条目 149 条 vs 干净装机 101 条）。**单文件一律不带 `/r`。**

### 交付依赖集（wheels）与开发环境对齐

安装包用 `pack\wheels` 离线安装依赖（`pip install --no-index --find-links
wheels -r requirements.txt`，会一并解析传递依赖），**该目录就是交付物**。
⚠️ 其中二进制 wheel（psycopg2/pywin32/pillow/lxml 等）与构建机 Python
小版本绑定（当前全为 **cp311**），安装器在检测到同目录 wheels\ 时会把
Python 门槛收紧为 **3.11.x**（在线安装无 wheels 时仍允许 3.10+）。
发布前核对它与开发 venv 是否一致：

```powershell
venv\Scripts\python.exe -m pip install --no-index --find-links pack\wheels -r requirements.txt --dry-run
# 再逐包比对包名+版本：两边应完全一一对应（实测 40/40）
```

> `pip install --upgrade -r requirements.txt --dry-run` **发现不了这类漂移**：
> `--upgrade -r` 不升级传递依赖（实测只报 5 个包，而实际有 18 个版本不一致）。
> 曾因此把 flask-caching 2.5.1（删除小写后端名垫片、与模板里的 `cache_type=simple`
> 不兼容）随包交付，**装机即崩**。

**版本唯一来源是项目根的 `constraints.txt`**（容器镜像按它钉版本；
`build-installer.ps1` 也按它 `pip download` 离线 wheels，保证两个交付通道是
同一组依赖；`tests/test_review_fixes_0925.py` 在 wheels 存在时会比对二者）。
升级依赖时：**先**修改 `constraints.txt` 并在开发环境验证，**再**运行构建脚本
重新下载 wheels（`--only-binary=:all:`）。如果手工替换了 wheels，则反过来按
wheels 反推并同步 `constraints.txt`：

```powershell
venv\Scripts\python.exe -c "import pathlib,re;[print(re.sub(r'[-_.]+','-',w.name.split('-')[0]).lower()+'=='+w.name.split('-')[1]) for w in sorted(pathlib.Path('pack/wheels').glob('*.whl'))]"
# 把输出替换进 constraints.txt 的版本行（pywin32 行保留 ; sys_platform == 'win32' 标记）
```

## 四、安装脚本行为（安装时会经历什么）
双击安装包后，`installer.nsi` 按顺序执行以下动作：

1. **安装向导页面**：欢迎 → 环境检测（缺什么会提示）→ 授权许可（须同意）
   → 选择安装路径 → 填写 PostgreSQL 连接信息（数据库地址/账号/密码）
2. 把运行所需文件复制到 `C:\Program Files\ITstudy\`（默认路径）
3. 把安装向导填写的数据库信息写入安装目录的 `postgresql.txt`
4. 创建 `data`、`logs`、`instance`、`venv` 等运行目录
5. 创建 Python 虚拟环境并安装 `requirements.txt` 中的依赖（首次较慢，需联网）
6. 注册并启动 `ITstudy` Windows 服务（开机自启）
7. 创建开始菜单和桌面快捷方式
8. 写入卸载信息和注册表项（控制面板可卸载）

> **升级安装（覆盖到已有目录）**：脚本在复制文件前会静默执行 `net stop ITstudy` 停掉
> 正在运行的旧服务——服务在跑时 `python.exe`、依赖 dll、前端文件被进程占用，随后的
> 覆盖会失败（安装中止在半途）。服务不存在或未运行时该命令返回非 0，**属正常情况**，
> 安装继续。

## 五、构建前检查（发布前逐项确认）
- `pack\installer.nsi` 中 `PRODUCT_VERSION` 为 `6.1.0`（安装包文件名会跟随）。
- `pack\license-v6.0.txt` 内容与授权要求一致（UTF-8 BOM，供安装后阅读）。
- `pack\license-v6.0.rtf` 与 `license-v6.0.txt` 内容一致，供 NSIS 授权页显示。
- `constraints.txt` 由安装器一并打包到安装目录；离线/在线 pip 安装均通过 `-c` 使用它，确保交付依赖版本固定（含 SQLAlchemy 2.0.x）。
- `pack\assets\` 下 `app.ico`、`nsis-header.bmp`、`nsis-welcome.bmp` 三个素材齐全。
- `requirements.txt` 可在目标网络环境下安装（离线环境需准备 wheel 包）。
- `itstudy_service.py` 位于项目根目录（安装后与 `app` 目录同级）。
- 本地运行数据、日志、缓存或敏感配置（如 `data/`、`logs/`、`instance/` 内容）
  **不要**封进安装包——安装时会自动重建空目录。
- `pack\wheels` 与开发 venv 的包版本一致（见 §三 末的核对命令）——**交付依赖集
  就是它**，漂移会随包发到客户机上。
- `installer.nsi` 的单文件 `File` 命令**不得带 `/r`**，并按 §三 的 `/V4` 打包清单
  核对一次（`site-packages` 必须 0 命中）。

## 六、安装后验证（装完确认能用）
安装完成后，**以管理员权限**打开 PowerShell：

```powershell
Get-Service ITstudy
```

**预期结果**：服务状态为 `Running`。然后浏览器访问：

```text
http://localhost:5000          （学生登录页，能打开即基本成功）
http://localhost:5000/admin/login   （管理端登录页）
```

> 管理端首次登录：服务方式安装没有可见控制台，随机初始密码在
> `C:\Program Files\ITstudy\admin_account.initial.txt`（仅管理员可读，
> 首次登录成功后自动删除）；也可在安装前设 `ADMIN_INIT_PASSWORD` 预置。

**如果服务没启动**，按顺序检查：

| 检查项 | 位置 |
|--------|------|
| 数据库连接信息是否正确 | `C:\Program Files\ITstudy\postgresql.txt` |
| PostgreSQL 服务是否运行、账号是否允许本机连接 | 服务管理器 / pg_isready |
| 虚拟环境是否创建成功 | `C:\Program Files\ITstudy\venv\Scripts\python.exe` 是否存在 |
| 应用启动报错 | `C:\Program Files\ITstudy\logs\app.log` |
| Windows 服务日志 | 事件查看器 → Windows 日志 → 应用程序 |

**还要验证服务能真的停下来**（只看 `Running` 不算过）：

```powershell
sc.exe stop ITstudy     # 应在数秒内变为 Stopped
sc.exe start ITstudy    # 再启动一次
```

> 这两个坑历史上都踩过：① pywin32 默认的服务宿主 exe 在 venv 下不可用，服务
> **从未真正启动过**（`net start` 报 **2186「服务没有响应控制功能」**，事件日志只有
> 一行无消息文本的错误、应用日志一行没有）；② 服务起来后**永远停不下来**（卡在
> `StopPending`，升级/卸载/重启全线受阻——安装程序在覆盖前也要先停服务）。
> 两者均已修（详见 `itstudy_service.py` 内的注释），但**必须实际 stop 一次**才算验证过。

## 七、常见问题

| 症状 | 原因与解决 |
|------|------------|
| `makensis` 找不到 | 未安装 NSIS 或未加入 PATH：安装 NSIS 3.x，或把其安装目录加入 PATH |
| 依赖安装失败 | 目标机器无法访问 Python 镜像源：提前准备离线 wheel 包并调整安装脚本 |
| 服务注册失败 | 未以管理员身份运行安装包；或 `pywin32` 安装失败（看安装日志） |
| 服务启动失败 | 先手动执行安装目录虚拟环境的 Python：`venv\Scripts\python.exe -c "from app import create_app"`，能导入说明应用代码正常，再查数据库连接 |
| 安装后打不开页面 | 见「六、安装后验证」检查表，最常见是 `postgresql.txt` 连接信息不对 |

## 八、项目结构（安装包会打包哪些内容）
以下为 ITstudy v6.1.0 当前根目录的主要结构（安装后实际位于
`C:\Program Files\ITstudy\`）。**带 ✅ 的目录会被打包进安装包**，
其余为运行期自动创建：

```text
ITstudy\
  app\                 ✅ Flask 应用包（模型、路由、服务层）
  templates\           ✅ Jinja2 页面模板
  static\              ✅ 前端静态资源、图标、脚本、样式和第三方前端库
  static\uploads\      真实上传根目录（资源/网盘/Python 文件；安装时预建空目录）
  static\homework\     作业附件（安装时预建空目录）
  static\submissions\  学生提交文件（安装时预建空目录）
  static\chunks\       分块上传临时区（安装时预建空目录）
  static\question_img\ 题目图片（安装时预建空目录）
  frontend\            ✅ SPA 管理端前端
  migrations\          ✅ 数据库迁移文件
  docs\                ✅ 项目说明、部署说明等文档
  tests\               pytest 测试用例（不随安装包分发）
  tools\               ✅ 维护工具（日志归档、静态压缩、密码重置等）；
                       e2e_*.py / review_*.py 为开发期回归与审查脚本（依赖 Playwright、
                       连隔离测试库），**不随安装包分发**（容器镜像同样排除）
  pack\                NSIS 封装脚本、素材、授权文本与封装指南（不随安装包分发）
  app.py               ✅ 应用入口
  itstudy_service.py   ✅ Windows 服务入口
  requirements.txt     ✅ Python 依赖清单
  cdn_config.json      ✅ CDN 清单生成物（运行时不读取，生效清单见 resource-loader.js）
  run_zh.bat           ✅ 本地启动脚本
  LICENSE              ✅ 项目根授权文件
  README.md            ✅ 项目入口说明（快速入口/核心能力/开发与回归命令）
  pack\nssm.exe        可选工具：将 Nginx 注册为 Windows 服务（部署期使用，不随安装包分发）
  data\                运行数据目录（安装时创建空目录，运行期自动填充）
  logs\                运行日志目录（同左）
  instance\            Flask 运行期配置（同左，首次启动自动生成 secret_key 与 deploy.conf）
  venv\                虚拟环境（安装时创建）
  wheels\              离线 wheel 包（build-installer.ps1 自动 pip download 生成；
                       安装器检测到同目录 wheels 时离线安装，缺失回退在线镜像。
                       断网机房部署前必须随 Setup.exe 一同携带。
                       注意：二进制 wheel 与构建机 Python 小版本绑定，
                       下载须用与目标机相同小版本的 Python 执行）
  backups\             日志归档（tools/archive_logs.py 生成；卸载时两个选项都会清理）
```

## 卸载数据选项

卸载程序会询问"是否同时删除运行数据"：
- **否（推荐）**：保留 instance（密钥/配置）、data、static（真实上传数据在
  `static\uploads`、`static\homework`、`static\submissions`、`static\question_img`、
  `static\chunks`）——重装后数据无损；旧版根目录 `uploads` 若为空会被顺手移除，
  若仍含历史 `.url` 外链文件则原样保留；
- **是**：以上目录连同 static 与旧版 `uploads` 全部删除，恢复出厂状态。

> **两个选项都会清理 `backups`（日志归档）**：它是 `tools/archive_logs.py`
> 已导出日志的副本，保留无实际价值且体积随运行持续增长。这一点在卸载
> 确认弹窗里也已如实写明。

> **打包边界原则**：只打包"代码和资源"，不打包"运行数据"——
> `data`、`static\uploads|homework|submissions|chunks|question_img`、`logs`、
> `instance` 里的开发机用户数据、日志、缓存、敏感配置一律不封进安装包；
> 安装时创建空目录，首次启动自动初始化。
