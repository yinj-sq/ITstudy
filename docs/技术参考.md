# ITstudy 技术参考（开发者 / 运维）

> **这份文档写给谁？** 需要配置 Nginx、调整性能参数、排查部署问题、或参与开发维护的人。
> 普通老师/管理员安装和使用 ITstudy，只需要看
> [README](../README.md)，本文可以跳过。

适用版本：`V6.1.0`

---

## 一、技术栈

| 层次 | 技术 | 用途 |
|------|------|------|
| 后端 | Flask 3.x + Waitress | Web 应用与生产 WSGI 服务 |
| 数据 | Flask-SQLAlchemy + Flask-Migrate + PostgreSQL | 数据模型、迁移与业务数据存储 |
| 缓存 | Flask-Caching（默认单进程 `SimpleCache`） | 高频查询缓存；多进程可切 `FileSystemCache` 或 Redis |
| 压缩 | flask-compress | gzip / brotli 响应压缩 |
| 页面 | Jinja2 + Bootstrap 5 + FontAwesome + Chart.js | 三端页面、组件与统计图表 |
| SPA | `frontend/`（免构建 Vue 3） | `/app` 管理端界面 |
| 文档预览 | JitViewer | PDF、Office、OFD、Markdown、代码、图片等在线预览 |
| 在线 PPT | PPTist | PPTX 导入、编辑、放映 |
| 打包 | NSIS | Windows 安装包 |

## 二、目录结构

```text
ITstudy/
  app.py                  应用入口（生产用 itstudy_service.py 或 run_zh.bat）
  itstudy_service.py      Windows 服务入口
  run_zh.bat              本地一键启动
  requirements.txt        Python 依赖
  constraints.txt         钉死的依赖版本（离线安装/容器共用）
  app/                    Flask 应用（模型、路由、服务层）
  templates/              Jinja2 页面模板
  static/                 静态资源与业务上传文件
  frontend/               SPA 管理端（入口 /app）
  migrations/             数据库迁移
  docs/                   文档与部署样例
  pack/                   安装包构建脚本与素材
  tests/                  pytest 回归测试
  tools/                  维护工具（压缩、归档、密码重置等）
  data/                   运行期缓存（可删除，自动重建）
  logs/                   运行日志（app.log）
```

> `data/`、`logs/`、`instance/`、`venv/`、`__pycache__/`、`.pytest_cache/` 是本机运行/测试产物，
> 删除后会自动重建，不属于交付文件。

## 四、Nginx 反向代理（完整 8 步）

> 适用：Windows 单机部署，想用 80/443 或域名访问；同一台机器已有其他站点时也可按此共存。
> 示例配置见 [itstudy.conf](itstudy.conf)。

无其他站点的机器可简化第 5～6 步，并把 `listen 8081` 改成 `listen 80`。

### 第 1 步：解压 Nginx

解压到 `C:\nginx\`（或使用学校已有的 Nginx）。

### 第 2 步：复制配置

把 `docs/itstudy.conf` 复制到 `C:\nginx\conf\conf.d\itstudy.conf`。

### 第 3 步：在 nginx.conf 中引入

编辑 `C:\nginx\conf\nginx.conf`，在 `http {}` 块内追加：

```nginx
include conf.d/itstudy.conf;
```

> 如果现有 `nginx.conf` 是逐个列出配置文件（而不是 `conf.d/*.conf` 通配），
> 必须手动加上这一行，否则配置不生效。

### 第 4 步：修改配置里的 3 个地方

| 参数 | 改成 | 说明 |
|------|------|------|
| `root C:/ITstudy;` | 实际安装根目录 | 公共静态资源直服；**必须用 `root`，不能用 `alias`**。路径含空格要加引号 |
| `server_name localhost 127.0.0.1;` | 你的域名或访问 IP | 需与应用 `TRUSTED_HOSTS` 一致 |
| `listen 8081;` | 无其他站点时改回 `listen 80` | 有共存站点时保留 8081 |

> **不要用 Nginx 直接托管上传目录。** `/static/uploads/`、`/static/homework/`、
> `/static/submissions/`、`/static/chunks/` 必须代理回应用（示例配置已写好），
> 由应用做归属鉴权和可见性校验；否则学生的作业、网盘文件可能被匿名下载。

### 第 5 步（共存场景）：确认端口不冲突

| 站点 | 端口 | server_name |
|------|------|-------------|
| 已有站点 A（示例） | 80 | `_`（通配） |
| 已有站点 B（示例） | 8080 | `_`（通配） |
| ITstudy（本项目） | **8081** | 你的域名 / IP |

> 不要与通配站点共用 80——通配 server 会抢走内网 IP 直访流量。
> 换端口前先 `netstat -ano | findstr :<端口>` 确认空闲。

### 第 6 步：应用侧也要配（关键）

Nginx 无法替应用设置环境变量，需在 `instance/deploy.conf` 或系统环境变量中设置：

```ini
trust_proxy_headers=1          # 信任 X-Forwarded-For / X-Real-IP
trusted_hosts=你的域名或IP     # 与 nginx server_name 一致
cookie_secure=1                # 仅 HTTPS 部署时设置
```

### 第 7 步：检查并启动

```powershell
cd C:\nginx
.\nginx.exe -t          # 语法检查，出现 "syntax is ok" 才继续
start nginx             # 启动；已启动时用 .\nginx.exe -s reload
```

### 第 8 步：验证

- 浏览器访问 `http://<服务器IP>:8081/`，学生登录页能打开且样式正常；
- 上传一个文件，确认分块上传与断点续传正常；
- 未登录直接访问学生附件直链，应被拒绝（403/重定向）；
- 管理端登录后查看 `logs/app.log` 无异常。

### 常用命令

```powershell
cd C:\nginx
.\nginx.exe -t          # 语法检查
.\nginx.exe -s reload   # 重载
.\nginx.exe -s stop     # 停止
```

**注册成 Windows 服务**（使用 `pack/nssm.exe`）：

```powershell
nssm install Nginx       # Path: C:\nginx\nginx.exe；Startup directory: C:\nginx\
net start Nginx
net stop Nginx
```

### HTTPS

启用 HTTPS 后建议同时设置：

```ini
COOKIE_SECURE=1
TRUSTED_HOSTS=你的域名,localhost
TRUST_PROXY_HEADERS=1
```

Nginx 需保留以下代理头：

```nginx
proxy_set_header Host $host;
proxy_set_header X-Real-IP $remote_addr;
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
proxy_set_header X-Forwarded-Proto $scheme;
proxy_set_header X-Forwarded-Host $host;
```

### 静态资源与新版本

- `/static/` 由 Nginx 直服并开启 `gzip_static`，升级后请使用安装包，或运行
  `python tools/precompress_static.py --refresh-only` 校准 `.gz`，避免旧 `.gz` 覆盖新 JS/CSS。
- 手工替换 CSS/JS 时，**必须同步替换同名 `.gz` 文件**；否则浏览器仍拿到旧版本。
- 化学仿真帧的 CSP 由应用下发；若 Nginx 额外添加 `Content-Security-Policy`，
  必须保留 `'unsafe-eval' 'wasm-unsafe-eval'`、`worker-src 'self' blob: data:`
  以及 `connect-src` 中的 `/static/chem-lab/`，否则 Ketcher 编辑器无法启动。

## 五、部署调优参数（`instance/deploy.conf`）

首次启动会生成带注释的模板；改完重启 ITstudy 生效（`ai_max_concurrent_streams`
保存后即时生效）。优先级：**环境变量 > deploy.conf > 内置默认值**。

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `cache_type` | `SimpleCache` | 单进程默认；多进程改 `FileSystemCache`。Redis 需额外安装 `redis` 包 |
| `cache_dir` | `data/cache` | `FileSystemCache` 的缓存目录 |
| `cookie_secure` | `0` | HTTPS 部署设 `1`；纯 HTTP 不要设 |
| `trusted_hosts` | 空 | Host 白名单，逗号分隔，**不要带端口** |
| `trust_proxy_headers` | `0` | 在可信反向代理后设 `1`；直接暴露不要设 |
| `proxy_secret` | 空 | 代理密钥，配合上一项；反代注入 `X-Proxy-Secret` |
| `login_ip_global_max_fails` | `50` | 单 IP 登录失败上限；大 NAT 可调到 100–150 |
| `student_ai_private_hosts` | 空 | 学生自填 AI 地址允许访问的私网白名单，防 SSRF |
| `ai_max_concurrent_streams` | `16` | AI 流式对话全进程并发上限（超出返回 429），管理端可运行时修改 |
| `waitress_threads` | `48` | Waitress 工作线程数（8–128），重启后生效；连接池会同比放大 |
| `quiz_analysis_cache_seconds` | `45` | 逐题分析聚合缓存秒数；`0` 关闭 |
| `large_download_pool_size` | `8` | 大文件下载专用线程池并发名额；`0` 关闭 |
| `large_download_threshold_mb` | `16` | 进入专用下载池的文件大小阈值（MB） |

> 调高 `waitress_threads` 前请确认 PostgreSQL `max_connections` 有余量
> （默认 100），连接池按线程数自动放大。

## 六、性能与运维建议

- **压缩**：应用已内置 gzip/brotli；响应头出现 `Content-Encoding: gzip` 即正常，
  Nginx 不必重复开启 gzip。
- **缓存**：单进程用 `SimpleCache`；多进程用 `FileSystemCache` 或 Redis。
  切换后端后旧 `data/cache/` 可整体删除。
- **大文件**：下载支持 Range 断点续传；上传为流式落盘；附件下载达到阈值时进入
  专用下载池，名额用尽快速返回 503，避免拖慢整站。
- **日志归档**：`Log` 表只增不删，建议每月执行
  `python tools/archive_logs.py`（默认归档 90 天前记录到 `backups/logs/`）。
- **AI 消息清理**：内置后台线程，默认保留 180 天、24 小时清理一次，可在管理端调整。
- **慢查询**：单条 SQL 超过 500ms 会记录 `[SLOW SQL]` 到 `logs/app.log`；
  动态页面超过 800ms 会记录“慢页面请求”。
- **会话校验**：学生会话校验缓存 10 秒；删除/停用学生或改密后最多 10 秒失效。
- **升级前**：建议先备份数据库和上传目录，或在 git 仓库中提交一次形成回滚点。

## 八、构建安装包与日志归档

构建 Windows 安装包（在项目根目录、PowerShell 中执行）：

```powershell
& .\pack\build-installer.ps1
# 输出：pack\ITstudy-v6.1.0-Setup.exe
```

> 构建脚本会自动下载离线 wheels、刷新预压缩 `.gz` 并调用 NSIS；详细说明见
> [pack/封装说明.md](../pack/封装说明.md)。

日志归档（项目根目录、venv 激活状态下）：

```powershell
python tools/archive_logs.py               # 归档 90 天前的日志到 backups/logs/
python tools/archive_logs.py --days 30     # 归档 30 天前
python tools/archive_logs.py --keep        # 仅导出不删除（试运行）
```

## 九、数据模型与蓝图（速查）

- 数据模型集中在 `app/models.py`；数据库迁移在 `migrations/`。
- 路由按业务拆分在 `app/blueprints/`（学生、教师、管理员、资源、作业、考试、
  问卷、课堂、网盘、AI、日志等）。
- 权限装饰器在 `app/decorators.py`；学生资源范围、教师任课范围、文件级隐藏
  分别在 `app/blueprints/resources.py` 与相关服务层实现。
- 新增/修改数据表时：先改模型，再补迁移，最后补回归测试；启动时会自动执行迁移。

> 具体模型字段、路由数量和蓝图清单随版本变化较快，建议直接阅读源码，不在文档里
> 维护容易过期的清单。
