# ITstudy 系统部署手册

> **这份文档从“把系统真正交付到学校”的角度重写。** 它不按功能菜单组织，而按
> 部署决策 → 环境准备 → 安装 → 初始化 → 验收 → 运维 → 升级/回滚的顺序展开。
>
> 适用版本：`V6.1.1` ｜ 读者：学校信息管理员、部署工程师、运维人员
> 日常使用说明见 [README](../README.md)；数据库细节见
> [PostgreSQL 指南](postgresql-guide.md)；容器细节见 [容器部署](容器部署.md)。

## 一、先做部署决策（不要先装软件）

在动手前，先和学校确认下面 8 件事。它们决定后面选哪种部署方式、需要哪些配置：

| 决策 | 选项 | 影响 |
|------|------|------|
| 装在哪种机器 | Windows 单机 / Windows + Nginx / Linux + Docker | 安装方式、端口、备份方式 |
| 访问范围 | 仅本机 / 局域网 / 公网域名 | 防火墙、Nginx、HTTPS、可信 Host |
| 是否用域名/HTTPS | 否 / 是 | Nginx 证书、`cookie_secure`、代理头 |
| 数据库位置 | 本机 / 另一台服务器 | 连接信息、防火墙、备份路径 |
| 数据放在哪 | 系统盘 / 独立数据盘 | 磁盘容量、备份策略 |
| 谁维护账号 | 管理员统一建 / 教师自建资源 | 教师账号、学科/年级/班级分配 |
| 学生名单来源 | Excel / 文本 / 手工 | 导入模板、年级口径 |
| 课程表谁维护 | 管理员统一 / 教师自行 | 课程表可选，不影响手动开课堂 |

> **结论先说**：课程表**不是必须项**。没有课程表也可以手动开启课堂；
> 管理员可统一配置，教师也可在「作息/课表」为自己任课班级添加。
> 学生名单推荐用 Excel 批量导入，不要一个个手工建。

## 二、部署拓扑

### 2.1 Windows 单机（最常见）

```text
教师/学生浏览器
      │ http://服务器IP:5000
┌─────▼─────────────────────────────┐
│ Windows 服务器                     │
│  ITstudy 服务（Waitress:5000）     │
│  PostgreSQL（本机 5432）           │
│  static/ 上传文件与离线仿真资源     │
└───────────────────────────────────┘
```

适合：一间机房、一所学校、无公网域名。安装包会自动注册 Windows 服务并开机自启。

### 2.2 Windows + Nginx（推荐给正式校园网）

```text
浏览器 ── http/https ── Nginx（80/443 或 8081）
                            │ 反代
                        Waitress:5000
                            │
                        PostgreSQL
```

适合：需要域名、HTTPS、多个站点共存、静态资源加速。
配置样例：[itstudy.conf](itstudy.conf)；完整步骤见
[技术参考 · Nginx 反向代理](技术参考.md#四nginx-反向代理完整-8-步)。

### 2.3 Linux + Docker

```text
浏览器 ── http/https ── Docker: app(8000) + db(5432)
```

适合：Linux 服务器、希望一条命令启动、可接受容器运维。
见 [容器部署指南](容器部署.md)。

## 三、环境与端口

| 项 | 要求 | 检查方式 |
|----|------|----------|
| 操作系统 | Windows 10/11 或 Windows Server；Linux 用 Docker | `winver` / `docker version` |
| Python | 3.10+（安装包自动建 venv） | `python -V` |
| PostgreSQL | 12+（推荐 16/17/18 稳定版） | `psql --version` |
| 磁盘 | 至少 20GB 空闲；课件多时按实际增加 | `df -h` / 资源管理器 |
| 内存 | 4GB 起；一间机房建议 8GB+ | 任务管理器 |
| 时间 | 必须准确，建议开 NTP | `w32tm /query /status` |
| 端口 | 5000（应用）/ 5432（数据库）/ 8081 或 80/443（Nginx） | `netstat -ano | findstr :5000` |
| 浏览器 | Edge/Chrome 最新版 | 打开登录页 |

> **端口不是随便选的**：5000 是应用默认端口；Nginx 示例用 8081 是为了和
> 同机其他站点共存；容器默认 8000。部署前先确认端口未被占用。

## 四、部署步骤（按方式选一条）

### 4.1 Windows 安装包

1. 安装 PostgreSQL，记录 5 项：主机、端口、数据库名、用户名、密码
   （见 [PostgreSQL 指南](postgresql-guide.md)）。
2. 双击 `ITstudy-v6.1.1-Setup.exe`。
3. 向导中填写数据库 5 项；安装程序自动建库、建虚拟环境、装依赖、注册服务。
4. 检查服务：
   ```powershell
   Get-Service ITstudy
   sc.exe stop ITstudy && sc.exe start ITstudy
   ```
   能启动、能停止才算通过。
5. 浏览器打开 `http://localhost:5000/`，看到学生登录页。

### 4.2 项目文件夹运行（已有 Python）

```powershell
run_zh.bat
```

它会检测环境 → 建 venv → 装依赖 → 迁移数据库 → 启动 Waitress。
成功标志：窗口不退出，浏览器能打开 `http://localhost:5000/`。

> 正式使用不要用 `python app.py`（单线程调试服务器）；请用 `run_zh.bat`
> 或 Windows 服务。

### 4.3 Docker（Linux）

```bash
DB_PASS='强口令' SECRET_KEY='随机串' ADMIN_INIT_PASSWORD='初始管理员口令' \
  docker compose up -d --build
curl -f http://127.0.0.1:8000/api/healthz   # {"status":"ok"}
```

详见 [容器部署指南](容器部署.md)。注意：容器端口是 **8000**，数据卷不能删。

## 五、初始化（决定系统是否“能用”）

部署完成 ≠ 可用。按下面顺序初始化，顺序不要反：

### 5.1 管理员登录

- 初始密码在 `admin_account.initial.txt`，或用 `ADMIN_INIT_PASSWORD` 预置。
- 首次登录后立即修改密码；忘记密码用 `python tools/reset_admin_password.py`。

### 5.2 建班级

- 「班级与考勤 → 班级信息」新建班级。
- 班级名称是课程表、学生导入、课堂大屏的**唯一匹配键**，不要随意改名。

### 5.3 建教师账号

- 「教师账号」创建教师：必须分配**学科、年级、任课班级**。
- 教师年级只有一个值；资源按年级授权时，以教师年级为准。
- 教师编辑模式可上传资源、布置作业、批改；只读模式只能进课堂。

### 5.4 导入学生（推荐 Excel）

- 「学生信息 → 批量导入」支持 Excel 和文本。
- 下载模板：列序为 `学号 / 姓名 / 班级 / 年级`。
- **年级请从模板下拉选择，并与教师账号的年级保持一致**（如高一、高二、高三）。
  年级不一致时，按年级授权的资源可能匹配不到；导入结果会给出提示。
- 班级不存在会自动创建；学号建议唯一；导入后生成统一临时密码，学生首次登录必须改。
- 名单来源可以是学籍系统导出、Excel 花名册或手工整理，不需要在平台里逐个建。

### 5.5 上传资源

- 管理员/教师上传课件、视频、资料，或添加外链资源。
- 大文件自动分块、断点续传；文件列表默认按需加载。
- **外链资源默认「打开（新标签页）」**；「站内打开（含 AI 助手）」是可选方式。
  对方站点返回 `X-Frame-Options` / CSP `frame-ancestors` 时，只能新标签页打开，
  不要尝试用代理剥离响应头。`/study/link` 和课堂外链条目都提供了新标签页逃生入口。

### 5.6 课程表（可选）

- **不是必须项**：没有课程表也可以手动开启课堂。
- 管理员可在「班级与考勤 → 课程表」统一配置；
- 教师编辑模式可在「设置 → 作息/课表」为自己任课班级添加/删除课程安排。
- 开启“课程表自动切班”后，系统会按课程表自动切换上课班级。

### 5.7 首次开课验收

- 教师登录 → 教学台 → 进入课堂 → 选择班级；
- 学生登录（需当前班级在上课）；
- 打开一个资源、投屏、点名、作业/考试各走一遍；
- 查看 `logs/app.log` 无异常。

## 六、配置基线

### 6.1 应用配置（`instance/deploy.conf` 或环境变量）

| 配置 | 生产建议 | 说明 |
|------|----------|------|
| `DB_PASS` | 强口令 | 不要用默认值 |
| `SECRET_KEY` | 固定随机串 | 多实例必须一致；丢失=全部重新登录 |
| `TRUST_PROXY_HEADERS` | 经 Nginx 时 `1` | 否则审计 IP 是代理地址 |
| `PROXY_SECRET` | 建议设置 | Nginx 注入同名头，防伪造转发 |
| `TRUSTED_HOSTS` | 域名/IP，逗号分隔 | 不要带端口 |
| `COOKIE_SECURE` | HTTPS 时 `1` | 纯 HTTP 不要设 |
| `WAITRESS_THREADS` | 48（默认） | 调高需确认数据库 `max_connections` |
| `CACHE_TYPE` | 单进程 `SimpleCache` | 多实例用 Redis/共享缓存 |
| `TZ` | `Asia/Shanghai` | 签到、课表、截止时间依赖它 |

### 6.2 Nginx（如使用）

- `/static/` 用 `root` 指向安装根目录，不要用 `alias`；
- `/static/uploads|homework|submissions|chunks/` **必须代理回应用**，不能直接静态服务；
- 升级后运行 `python tools/precompress_static.py --refresh-only`，避免旧 `.gz` 覆盖新文件；
- HTTPS 时保留 `Host`、`X-Real-IP`、`X-Forwarded-For`、`X-Forwarded-Proto`；
- 应用设置了 `PROXY_SECRET` 时，Nginx 必须发送同值的
  `proxy_set_header X-Proxy-Secret "..."`；否则应用不采信转发头，账号轨迹/限流
  会把来源记成 `127.0.0.1`。修改后 `nginx -t && nginx -s reload`。

### 6.3 数据库

- 连接信息写在 `postgresql.txt` 或环境变量；
- 备份用 `pg_dump`；恢复前先停应用；
- 不要用旧版 `pg_dump` 连新版服务端（容器内已带 PG16 客户端）。

## 七、备份、恢复、升级、回滚

### 7.1 备份（必须同时备份两部分）

1. 数据库：`pg_dump -h localhost -p 5432 -U postgres -d itstudy --no-owner --no-acl > backup.sql`
2. 文件：`static/uploads/`、`static/homework/`、`static/submissions/`、
   `static/question_img/`、`instance/secret_key`、管理员账号文件。
3. 备份放到另一块磁盘/另一台机器；至少保留最近 7 天。

### 7.2 恢复

停服务 → `psql -U postgres -d itstudy < backup.sql` → 恢复上传目录 →
启动服务 → 抽查附件/网盘文件下载、教师/学生登录。

### 7.3 升级

- Windows：再运行一次安装包（自动停旧服务、覆盖文件、重启；数据保留）。
- Docker：`docker compose build app && docker compose up -d app`。
- 升级前先备份；升级后跑一次验收清单。
- V6.1.0 升级会删除旧「铜匠实验室」资源及关联数据（不备份、不可恢复），需提前导出。

### 7.4 回滚

- 程序回滚：重装上一版安装包/镜像（数据库结构只向前迁移，不要手动降级）。
- 数据回滚：停服务 → 用备份 SQL 和文件覆盖 → 启动。
- 回滚前确认 `instance/secret_key` 与数据库、文件是同一批备份。

## 八、监控与日常巡检

| 项 | 频率 | 看什么 |
|----|------|--------|
| 服务状态 | 每日 | Windows 服务/容器是否 Running；`/api/healthz` |
| 日志 | 每日/异常时 | `logs/app.log` 的 ERROR、`[SLOW SQL]`、慢页面请求 |
| 磁盘 | 每周 | 上传目录增长、剩余空间 ≥10% |
| 数据库连接 | 每周 | `pg_stat_activity`；连接数接近上限要扩容 |
| 备份 | 每周 | 备份文件是否生成、能否恢复抽检 |
| 账号轨迹 | 按需 | 登录 IP、异常登录、未正常退出 |
| 时间同步 | 每月 | NTP 是否正常；课表/签到依赖本地时间 |

## 九、安全基线（部署时必须确认）

- 管理员初始密码已修改；默认 `admin/admin123` 不存在于生产。
- 数据库强口令；不把 5432 暴露到公网。
- 经 Nginx 时设 `TRUST_PROXY_HEADERS=1` + `PROXY_SECRET` + `TRUSTED_HOSTS`。
- 上传目录由应用鉴权，Nginx 不得直接托管。
- 上传 HTML 课件保持 opaque 沙箱；不要为方便关闭。
- AI 密钥保存在服务端；不要把密钥写进前端或文档。
- 定期检查账号轨迹与操作日志；离职教师账号及时停用。

## 十、部署验收清单（逐项打勾）

### 基础

- [ ] 服务能启动、能停止、能开机自启
- [ ] `http://服务器IP:5000/` 能打开学生登录页
- [ ] 管理端能登录，初始密码已修改
- [ ] PostgreSQL 服务在运行，`pg_isready` 正常
- [ ] 磁盘剩余 ≥10%，日志可写

### 初始化

- [ ] 已建至少 1 个班级
- [ ] 已建至少 1 个教师账号（学科/年级/班级齐全）
- [ ] 已用 Excel/文本批量导入学生，年级与教师一致
- [ ] 已上传至少 1 个资源（文件或外链）
- [ ] 课程表：已配置或明确“暂不配置、手动开课堂”
- [ ] 教师能进入课堂，学生能登录并看到资源

### 功能抽检

- [ ] 资源打开/预览/课堂投屏正常
- [ ] 作业发布/提交/批改正常
- [ ] 在线考试开始/交卷/批改正常
- [ ] 外链资源能打开；需要新窗口时能正常跳转
- [ ] 课件/GeoGebra/化学/硬件仿真至少各打开一个
- [ ] 账号轨迹有登录记录，IP 不是代理地址

### 运维

- [ ] 已完成一次数据库+文件备份，并抽检恢复
- [ ] 已配置 NTP 时间同步
- [ ] 已确认升级/回滚步骤与负责人
- [ ] 已记录数据库 5 项连接信息与管理员密码保管方式

## 十二、规模与容量提示

- 单实例 Waitress（48 线程）覆盖一间机房/一所学校常见规模。
- 多实例：统一 `SECRET_KEY`、共享缓存（Redis）、共享上传存储、
  Nginx 负载均衡，并按实例数核算 PostgreSQL `max_connections`。
- 课件/视频多时优先扩容磁盘与备份空间；大文件上传走分块，不需要调大单请求上限。
- 高并发考试前，先看 `[SLOW SQL]`/慢页面日志，再考虑加线程或加实例。

## 十三、出问题先看哪里

| 现象 | 先检查 |
|------|--------|
| 页面打不开 | 服务是否运行、端口是否占用、防火墙、`logs/app.log` |
| 学生登录不上 | 当前上课班级、学生是否停用、学号空格 |
| 样式/图片丢失 | Nginx `root` 路径、`/static/` 配置、`.gz` 是否过期 |
| 上传文件打不开 | 上传目录是否代理回应用 |
| 外链跳转失败/空白 | 目标站点可能禁止 iframe；用资源卡「打开（新标签页）」或课堂「在新标签页打开」 |
| 审计 IP 是 127.0.0.1 | `TRUST_PROXY_HEADERS=1`；Nginx 同时发送 `X-Real-IP`、`X-Forwarded-For` 与同值的 `X-Proxy-Secret` |
| 管理员密码忘记 | `python tools/reset_admin_password.py` |

更多见 [README · 常见问题](../README.md#46-常见问题) 与
[PostgreSQL 指南 · 常见问题](postgresql-guide.md#八常见问题)。
