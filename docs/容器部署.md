# ITstudy 容器部署指南（Docker / Linux · 小白版）

> **这篇文档写给谁？** 要把 ITstudy 装到 **Linux 服务器**上，并且会用一点 Docker 的人。
> 如果你用的是 **Windows 单机**，请直接看 [README](../README.md)——那种情况
> 不需要 Docker。
>
> **Docker 是什么（一句话）**：把 ITstudy 和它需要的数据库打包成两个“集装箱”，
> 一条命令就能启动，不用在服务器上逐个安装 Python、PostgreSQL。

适用版本：ITstudy `V6.1.0` ｜ 默认端口：`8000`

---

## 一、五分钟跑起来

**前提**：服务器已安装 Docker 和 Docker Compose。执行 `docker compose version`
能看到版本号即可。

在项目目录执行：

```bash
DB_PASS='你的数据库强口令' \
SECRET_KEY='一串随机字符' \
ADMIN_INIT_PASSWORD='初始管理员口令' \
  docker compose up -d --build

curl -f http://127.0.0.1:8000/api/healthz
# 返回 {"status":"ok"} 就是启动成功
```

三个变量建议都设置：

| 变量 | 作用 | 注意 |
|------|------|------|
| `DB_PASS` | 数据库密码 | **必填**；不设时 compose 直接报错，不再使用弱口令 |
| `SECRET_KEY` | 会话密钥 | 不设会自动生成并存到 `instance` 卷；**多实例必须显式设置成同一个值** |
| `ADMIN_INIT_PASSWORD` | 初始管理员密码 | 建议设置；不设则随机生成并打印到日志 |

> 容器默认以非 root 用户 `itstudy`（UID/GID 10001）运行。全新部署无感；
> 从旧版镜像升级需先修正数据卷属主，见第六节。

> 容器默认走 **8000 端口**（Windows 单机版是 5000，注意别搞混）。

## 二、它都带了什么

| 文件 | 作用 |
|------|------|
| `Dockerfile` | 基于 `python:3.11-slim`；依赖版本按 `constraints.txt` 钉死，与 Windows 安装包的离线包一致 |
| `entrypoint.py` | 启动时先等数据库就绪（最长 120 秒），再自动建库/建表/补字段，最后用 Waitress 监听 `0.0.0.0:8000` |
| `docker-compose.yml` | 一键编排：数据库（`db`）+ 应用（`app`），应用等数据库健康后再启动 |
| `.dockerignore` | 打包镜像时排除 `venv/`、`data/`、`logs/`、上传目录、测试代码等 |

## 三、数据卷：这些千万不能删

容器里的重要目录用 Docker 卷持久化。**卷丢了，对应的数据就没了**：

| 卷 | 里面存什么 | 丢了的后果 |
|---|---|---|
| `/app/instance` | 会话密钥、部署配置、管理员账号文件、AI 凭据等 | **所有人都要重新登录**；AI 凭据、管理员改过的密码失效 |
| `/app/static/uploads` | 课件 / 网盘 / Python 答案与参考文件 | 全部丢失 |
| `/app/static/homework` | 作业附件 | 全部丢失 |
| `/app/static/submissions` | 学生提交的文件 | 全部丢失 |
| `/app/static/chunks` | 分块上传临时区 | 升级时未传完的分块会中断 |
| `/app/static/question_img` | 题目图片 | 全部丢失 |
| `/app/data`、`/app/logs` | 缓存与日志 | 可重建，建议一起保留 |

> 具体挂载以 `docker-compose.yml` 为准（应用 8 个 + 数据库 1 个）。

**备份**：数据库用 `pg_dump`；文件部分至少备份 `app_instance`、`app_uploads`、
`app_homework`、`app_submissions`、`app_question_img` 这五个卷。
容器内已装 PostgreSQL 16 客户端，不要用宿主机上更旧版本的 `pg_dump` 去连 16 服务端。

## 四、常用操作

```bash
# 查看状态
docker compose ps

# 查看应用日志（首次管理员密码也会打印在这里）
docker compose logs -f app

# 停止
docker compose down

# 启动
docker compose up -d

# 升级（重新构建并启动应用）
docker compose build app && docker compose up -d app
```

数据库迁移会在启动时自动完成，数据卷不动。

> **从旧版 compose 升级**：旧版没有把管理员账号文件放进 `instance` 卷。
> 若旧容器还能访问，先复制出来再重建：
>
> ```bash
> docker compose cp app:/app/admin_account.txt ./admin_account.txt.bak
> docker compose up -d --force-recreate app
> docker compose cp ./admin_account.txt.bak app:/app/instance/admin_account.txt
> docker compose restart app
> ```
>
> 没有备份也不要紧：卷内没有旧账号文件时，应用会按 `ADMIN_INIT_PASSWORD`
> 或随机密码重新初始化，重置一次即可。

## 五、所有可设置的环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `DB_HOST` / `DB_PORT` / `DB_USER` / `DB_PASS` / `DB_NAME` | `db` / `5432` / `postgres` / **必填** / `itstudy` | 数据库连接；`DB_PASS` 未设置时 compose 报错 |
| `SECRET_KEY` | 空（自动生成并持久化） | 多实例必须显式设置且一致 |
| `APP_PORT` | `8000` | 宿主机映射端口 |
| `PORT` | `8000` | 容器内监听端口（一般不用改） |
| `WAITRESS_THREADS` | `48` | 工作线程数（8–128）；连接池按线程数自动放大 |
| `TZ` | `Asia/Shanghai` | 时区。签到、课表自动切班、作业截止都按本地时间判断 |
| `TRUST_PROXY_HEADERS` | `0` | 在可信反向代理后面时设 `1` |
| `PROXY_SECRET` | 空 | 代理密钥（配合上一项） |
| `TRUSTED_HOSTS` | 空 | Host 白名单，逗号分隔、**不要带端口** |
| `COOKIE_SECURE` | `0` | 整站 HTTPS 时设 `1` |
| `CACHE_TYPE` / `CACHE_DIR` | `SimpleCache` / `<项目根>/data/cache` | 单容器保持 `SimpleCache`；多实例需共享缓存 |
| `STUDENT_AI_PRIVATE_HOSTS` | 空 | 学生自填 AI 地址允许访问的私网白名单 |
| `LOGIN_IP_GLOBAL_MAX_FAILS` | `50` | 单个 IP 全局登录失败上限 |
| `AI_MAX_CONCURRENT_STREAMS` | `16` | AI 流式对话全进程并发上限 |
| `ADMIN_INIT_PASSWORD` | 空 | 全新部署的初始管理员密码 |
| `ADMIN_ACCOUNT_FILE` | `/app/instance/admin_account.txt` | 管理员账号文件位置（compose 已设） |
| `APP_CPUS` / `APP_MEMORY` | `2.0` / `2g` | 应用容器资源上限 |
| `DB_CPUS` / `DB_MEMORY` | `1.0` / `1g` | 数据库容器资源上限 |

> `CACHE_TYPE`、`COOKIE_SECURE`、`TRUST_PROXY_HEADERS`、`PROXY_SECRET`、
> `TRUSTED_HOSTS`、`STUDENT_AI_PRIVATE_HOSTS`、`LOGIN_IP_GLOBAL_MAX_FAILS`、
> `AI_MAX_CONCURRENT_STREAMS`、`WAITRESS_THREADS` 也可写进 `instance/deploy.conf`
> （同名小写键），优先级：**环境变量 > 配置文件 > 默认值**。
>
> **关于 Redis**：`CACHE_TYPE=RedisCache` 需要额外的 `redis` Python 包，它不在默认
> 依赖里。容器内启用前先安装：`docker compose exec app pip install 'redis>=5,<6'`，
> 并把这个步骤写进你自己的镜像构建/启动脚本；否则应用会因 `ImportError` 启动失败。
> 单容器用 `SimpleCache` 即可。

## 六、从旧版镜像升级：修正数据卷属主

旧版镜像以 root 运行，数据卷里的文件属主是 root；新容器以 `itstudy`（10001）运行，
会无法写入上传/日志目录。升级前执行一次（把 `<项目名>` 换成 `docker volume ls`
里的卷名前缀，默认由目录名决定；建议用 `COMPOSE_PROJECT_NAME=itstudy` 固定）：

```bash
docker compose down
docker run --rm \
  -v <项目名>_app_uploads:/v1 -v <项目名>_app_homework:/v2 \
  -v <项目名>_app_submissions:/v3 -v <项目名>_app_chunks:/v4 \
  -v <项目名>_app_question_img:/v5 -v <项目名>_app_data:/v6 \
  -v <项目名>_app_logs:/v7 -v <项目名>_app_instance:/v8 \
  alpine chown -R 10001:10001 /v1 /v2 /v3 /v4 /v5 /v6 /v7 /v8
docker compose up -d
```

## 七、和 Windows 单机版的区别

- **没有 Nginx**：容器直接暴露 Waitress 的 8000 端口。想加反向代理就自备一个，
  此时需要设 `TRUST_PROXY_HEADERS=1` + `PROXY_SECRET` + `TRUSTED_HOSTS`，
  HTTPS 时再设 `COOKIE_SECURE=1`，并照抄 `docs/itstudy.conf` 里的上传目录代理规则。
- **没有 nssm**：容器用 `restart: unless-stopped` 自己守护。
- **pywin32 自动跳过**：Windows 专用依赖在 Linux 下不会安装。
- **静态资源由应用直接提供**（可选再用 Nginx 加速）。

## 八、多实例部署（可选，进阶）

单实例 Waitress（48 线程）已覆盖一间机房/一所学校的常见规模。确需多实例时注意：

1. **会话与缓存**：所有实例设置**同一个 `SECRET_KEY`**，并把 `CACHE_TYPE`
   换成共享后端（Redis 需自行安装 `redis` 包）。`SimpleCache`/`FileSystemCache`
   不能跨实例共享，否则登录态、限流计数各自为政。
2. **数据库连接**：连接池按 `WAITRESS_THREADS` 自动放大。默认 48 线程约为
   `pool_size=40 + max_overflow=20`（上限 60），两实例即需 PostgreSQL
   `max_connections > 120`（默认 100）。
3. **后台线程**：网盘清理、AI 消息归档是进程内线程，多实例会重复执行
   （幂等但浪费）；建议只让一个实例承担。
4. **端口**：compose 的 `ports` 是固定映射，直接 `--scale app=2` 会冲突。
   多实例请去掉 `ports`，由前置 Nginx/Caddy 按服务名负载均衡。
5. **静态文件**：上传目录是本地卷；多实例需共享存储（NFS/对象存储），
   或让静态请求固定回源到同一实例。

## 九、遇到问题

| 症状 | 先检查什么 |
|------|------------|
| `docker compose up` 报 `DB_PASS` 未设置 | 按第一节设置 `DB_PASS` 环境变量 |
| 应用启动后健康检查失败 | `docker compose logs app` 看数据库连接和迁移日志 |
| 首次登录不知道管理员密码 | `docker compose logs app` 查看随机密码，或看 `instance/admin_account.initial.txt` 卷文件 |
| 上传/日志写入失败 | 是否从旧版镜像升级；按第六节修正卷属主 |
| 页面能开但登录状态互相踢 | 多实例是否设置了同一个 `SECRET_KEY` 和共享缓存 |
| 时间差几小时 | `TZ` 是否为 `Asia/Shanghai` |

更多技术细节、Nginx/HTTPS、部署参数见 [技术参考](技术参考.md)；
数据库安装与备份见 [PostgreSQL 安装指南](postgresql-guide.md)。
